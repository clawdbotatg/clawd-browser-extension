# Skill: drive my real Chrome browser (clawd-browser)

My machine runs the Clawd Browser extension. A bridge at http://127.0.0.1:8765
lets you fully drive my real, logged-in Chrome: list/open tabs, read pages, take
screenshots, click, type, run JS. These are my live sessions and accounts — ask
before doing anything destructive or outward-facing (sending, posting, deleting,
buying).

## Where the bridge is
The bridge runs on the browser's machine and answers on the LAN too, so the
session driving it may be on another computer. If the base URL you were given
looks like http://<host>:8765/k/<token> you are (probably) on another machine:
the /k/… path is the access token, keep it on EVERY request, and use that base
wherever this text says http://127.0.0.1:8765 (the copy served at <base>/skill is
already rewritten for you). Never move the token to a URL that isn't this
bridge's.

## If you already have the MCP tools
Tools named mcp__clawd-browser__* talk to whatever bridge THEY were configured
for — on the browser's own machine that is this browser; on another machine it is
some other browser (or none). Use them only if browser_tabs lists the tab/url you
were given; otherwise ignore them and use the HTTP below.

## Otherwise: plain HTTP from your shell
Every action is one POST. Replies are {"ok":true,"result":{...}} or
{"ok":false,"error":"..."}.

  curl -s http://127.0.0.1:8765/status
    -> {"ok":true,"extension_connected":true}
  curl -s http://127.0.0.1:8765/cmd -d '{"cmd":"tabs"}'

If the connection is refused:
  - on the browser's own machine, start the bridge (repo path there):
      nohup python3 ~/clawd/clawd-harness/projects/clawd-browser-extension/bridge.py >/dev/null 2>&1 &
  - from another machine there is nothing to start — the bridge lives next to
    the browser. Tell me instead of retrying.
If it replies 403, you dropped the /k/<token>/ prefix from the URL.
If it says "extension not connected", Chrome with the extension isn't running —
tell me instead of retrying.

## Connections flap — a missing tab is usually NOT gone
Chrome suspends the extension's MV3 service worker whenever it feels like it,
which drops that browser's websocket until the next wake (seconds to ~a minute).
This is normal and self-healing. Consequences while a browser is mid-blip:

- "No tab with given id N" usually means the tab's OWNING browser is briefly
  disconnected (your command got routed to a different connected browser), not
  that the tab was closed. Retry the same call every few seconds for ~60s
  before drawing any conclusion.
- "tabs" only lists browsers connected AT THIS INSTANT. A tab absent from the
  list is not evidence it's closed — especially if another browser's tabs are
  what came back. Re-poll; the tab reappears when its browser reconnects.
- Connection ids in GET /status change on every reconnect, so a changed id is
  a reconnect, not a different browser — and pinning {"target":...} by id goes
  stale for the same reason. After a blip, re-find the tab by URL via "tabs".
- Only conclude the browser is really gone if it stays absent for ~2 minutes
  of re-polling — then tell me instead of guessing.

## Commands
POST /cmd with {"cmd":<name>,"args":{...}}. Omitting tab_id targets the active
tab; get tab_ids from "tabs".

  tabs        {}                                  -> every tab: tab_id, url, title, active, window_id, status
  open        {url}                               -> new tab, waits for load
  navigate    {tab_id?, url}                      -> point a tab somewhere, waits for load
  close_tab   {tab_id?}
  read        {tab_id?, max_chars?}               -> page innerText + title/url (default 20k chars)
  screenshot  {tab_id?}                           -> {"result":{"data":<base64 png>}} — works on unfocused tabs
  eval        {tab_id?, code}                     -> run JS in the page, returns the value
  click       {tab_id?, js} or {tab_id?, selector} or {tab_id?, x, y}
              -> real trusted click (scrolls target into view). js = expression
                 returning the Element to click — found, measured, and clicked
                 atomically (no stale coordinates); prefer it on dynamic pages.
                 Reply echoes the element's tag+text so you can verify the target.
  wait_for    {tab_id?, js? selector?, timeout_ms?, poll_ms?}
              -> poll until selector matches / js returns truthy (default 15s);
                 returns {ready, value, waited_ms}, ready=false on timeout.
                 Use instead of sleeping and hoping the page rendered.
  type        {tab_id?, text, selector?, submit?} -> clicks selector to focus, inserts text; submit=true presses Enter
  key         {tab_id?, key}                      -> Enter, Tab, Escape, Backspace, Delete, ArrowUp/Down/Left/Right, Home, End, PageUp, PageDown, Space
  console     {tab_id?, limit?, clear?}           -> captured console logs (capture starts on first use)
  detach      {tab_id?}                           -> remove Chrome's "is being debugged" banner from a tab
  version     {}                                  -> running extension code version
  reload_extension {}                             -> extension reloads itself (picks up edited code from disk)

## Screenshot recipe
  curl -s http://127.0.0.1:8765/cmd -d '{"cmd":"screenshot","args":{"tab_id":123}}' \
   | python3 -c 'import sys,json,base64; open("/tmp/clawd-shot.png","wb").write(base64.b64decode(json.load(sys.stdin)["result"]["data"]))'
Then Read /tmp/clawd-shot.png to look at it.

## Notes
- Several browsers (Chrome + Canary, each with the extension) can be connected
  at once. The bridge routes for you: "tabs" lists every browser's tabs (each
  tagged with a "browser" connection id), a tab_id goes to whichever browser
  owns it, and commands without a tab_id go to the newest browser that has
  windows. To pin one explicitly add {"target":"<id-prefix or UA substring>"}
  at the top level of the /cmd body (ids from GET /status).
- chrome:// pages are off-limits (Chrome blocks extensions there).
- Clicks/typing are trusted CDP input events — they work on React apps and don't
  need the tab focused, so you can drive background tabs silently.
- Prefer read/eval to extract data; screenshots for visual verification.
- To get these as native MCP tools in future sessions (on the browser's machine):
  claude mcp add clawd-browser --scope user -- python3 ~/clawd/clawd-harness/projects/clawd-browser-extension/mcp_server.py
  From another machine that has this repo, point the same server at the LAN bridge:
  claude mcp add clawd-browser --scope user -e CLAWD_BROWSER_URL=http://<host>:8765/k/<token> -- python3 /path/to/mcp_server.py
